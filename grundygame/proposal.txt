1. Abstract
This project proposes the development of a highly proficient AI agent capable of playing Grundy's Game, a two-player impartial combinatorial game. The core of the project is to explore classical game-playing theory by implementing a "perfect" opponent using the Minimax algorithm, which is a foundational concept in adversarial search. The AI's logic will be grounded in the mathematical principles of the Sprague-Grundy theorem. The final deliverable will be a professional, interactive web application where a user can challenge this unbeatable AI, providing a practical and visual demonstration of game theory and strategic search algorithms in action.
2. Chosen Topic and Rationale
This project directly aligns with the approved topic of "Monte Carlo Tree Search and Game playing."
Rationale: Grundy's Game is a classic example of a perfect information, zero-sum, adversarial game. Such games have historically served as fundamental benchmarks and learning environments for AI. The primary goal of this domain is to develop algorithms that can search through a "game tree" of possible future moves to determine the optimal strategy.
Core Algorithm: While the topic includes Monte Carlo Tree Search (MCTS), this project will begin by implementing the Minimax algorithm, which is the canonical starting point for all deterministic game-playing AI. Minimax provides the theoretical foundation for more advanced techniques like MCTS by establishing the principles of minimizing the opponent's maximum possible score. Understanding and implementing Minimax is a prerequisite for appreciating why and how MCTS is used in more complex games (like Go or Chess) where the game tree is too vast to be explored completely.
Connection to MCTS: By successfully creating a perfect player for a solvable game like Grundy's, this project provides a solid baseline. It sets the stage for a comparative analysis where one could later implement MCTS to see how it approximates the optimal strategy in situations where the "perfect" Minimax solution might be computationally intractable.
3. Project Goals and Objectives
The primary goal is to create a web-based application that allows a human to play Grundy's Game against a logically unbeatable AI.
Objective 1: Implement the Game Environment: Develop a robust Python backend that correctly enforces the rules of Grundy's Game (a heap can only be split into two smaller, unequal heaps).
Objective 2: Develop the AI Player:
Implement the core decision-making logic using the Minimax search algorithm.
Leverage the mathematical properties of the Sprague-Grundy theorem (calculating Nim-values) to find the optimal move with maximum efficiency.
Objective 3: Build an Interactive Frontend:
Design a clean, professional, and intuitive web interface using HTML, CSS, and JavaScript.
Create clear visual feedback for the player’s moves and, crucially, for the AI's moves, including animations to show which heap is selected and how it is split.
Objective 4: Integrate and Deploy: Connect the Python/Flask backend with the frontend to create a seamless, fully functional application.
4. Methodology and Implementation Plan
The project will be executed in four distinct phases:
Phase 1: Game Logic and Backend Foundation (Python & Flask)
Define the data structures to represent the game state (the collection of heaps).
Create functions to validate player moves and check for terminal (win/loss) conditions.
Set up a Flask web server with API endpoints to handle game initialization (/start) and player moves (/move).
Phase 2: Core AI Engine (Minimax & Game Theory)
Implement a recursive function to calculate the Grundy number (or Nim-value) for any given heap size. This is the core of the AI's strategic knowledge.
Develop the AI's find_best_move function. This function will analyze the current game state's overall Nim-sum and identify a move that transitions the game to a state with a Nim-sum of zero, thereby guaranteeing a win if played optimally. This is the practical application of the Minimax principle in an impartial game.
Phase 3: Frontend User Interface (HTML, CSS, JS)
Structure the web page with HTML to include a game setup area, a dynamic game board, player controls, and message displays.
Style the application using modern CSS for a professional look and feel, including creating circular "heap" elements and a responsive layout.
Implement the client-side logic in JavaScript to handle user interactions, animate both the user's and the AI's moves, and communicate with the Flask backend via asynchronous API calls (Fetch API).
5. Project Deliverables
A Fully Functional Web Application: A deployed web application where users can play Grundy's Game against the AI.
Source Code Repository: A well-documented Git repository containing all backend (Python) and frontend (HTML/CSS/JS) code.
Final Project Report: A detailed report covering the project's architecture, the theory behind the Minimax algorithm and the Sprague-Grundy theorem, implementation challenges, and a user guide.
Live Demonstration: A presentation demonstrating the application's features and the AI's unbeatable strategy.
6. Potential Extensions and Future Work
This project serves as an excellent foundation for exploring more advanced AI topics.
Reinforcement Learning (RL) Agent: A fascinating extension would be to build an RL agent (e.g., using Q-learning) that learns to play Grundy's Game from scratch by playing against itself. The goal would be to see if the RL agent can independently discover the optimal strategy that the Minimax agent was explicitly programmed with. This would provide a direct comparison between classical search-based AI and modern learning-based AI.
MCTS Implementation: For a larger, more complex game, we could replace the Minimax/Nim-value solver with an MCTS-based agent to see how it performs when a perfect solution is not easily computable.
